# Launch Checklist

## Before Posting

- Confirm the latest Release has a downloadable exe.
- Confirm the README demo GIF loads on GitHub.
- Confirm Issues are enabled and templates show up.
- Use the `/releases/latest` download link instead of a version-specific link when posting.
- Keep the first post focused on one promise: fast Windows task capture by hotkey.

## During Posting

- Add the demo GIF or social preview image where the platform supports media.
- Say clearly that the exe is unsigned because this is a personal developer app.
- Ask for specific feedback instead of general praise:
  - Does the hotkey feel right?
  - Does the popup position feel natural?
  - Is the reminder flow clear?
  - Does SmartScreen block adoption?

## After Posting

- Reply to every serious bug report.
- Convert repeated comments into GitHub Issues.
- Tag issues with `bug`, `enhancement`, or `question`.
- Ship a small `v0.2.2` if there are quick fixes.
- Only then post to larger English communities.

## Metrics To Watch

- GitHub stars
- Release downloads
- Issue count and repeated themes
- Referring sites in GitHub Traffic
- Comments that mention friction before download or first launch
